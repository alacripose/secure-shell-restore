How a loop transformer works

actually work? So, a normal transformer runs every layer once from the input right through to the output. What Dory does is it splits its layers into three separate blocks. There's an input block at the start and an output block at the end. And each of those only runs once. The middle bit is where we've got the recurrent block. And that's the part that loops. If we sort of look at how those layers are actually spread out, you've got 16 for the input block, got 16 for the output, and then you've got the recurrent block, which is actually 40 layers. So, if you look at the animation here, what you're seeing here is a token going round that recurrent block. And we can set it to be once round, twice round, four times round, eight times round. And you can think of it as those representations as it goes through the recurrent part are just refining those representations to get better and better now. So it doesn't go totally off on its loops. You can see that it's actually sort of readding what came out of the input block to it each time. So in many ways it's very much like the ResNet models where you've got the original input being added to a modification of it. The difference here is just that that modification rather than being different sets of weights each time for each block, it's basically the same set of weights that are just getting reinforced here. So you can kind of think of this as every lap that it goes through, the model gets reminded of what the token is actually working on. So in some ways, it's kind of like rereading the question or rereading the input basically before you have another shot at getting the best output. Now, if we were to unroll it like this, you can see that we're getting a much deeper model here. Even though the weights for that repeated block are the same each time, compute-wise, we've got a lot more depth going on there. The other thing that's interesting here, and that makes it perhaps more practical, is that the output block is trained to read the state after any of the loops. So, one loop, two loops, four loops are all valid models for this. You don't have to retrain it for any particular number of loops. You can basically just set that at inference time and you're making use of eight times through these shared weights. So this whole idea is what Nvidia calls this elastic inference compute. And as I turn up these loops here, the compute per token is going up, but the weights in memory don't change at all. In this case, it's still only 3.9 billion parameters sitting on the GPU. So already you should start to see that one of the huge advantages of this is that if we can just loop through the same weights multiple times, we don't need to have GPUs with huge amounts of memory to be able to run a model like this. And you can see here at one loop, we've basically got 72 layers of effective depth. At two loops, we're up to 112. If we jump to four loops, we're already at 192 layers there.
